Lesson 02 — Đưa code lên Prefect HQ Server

4 bước từ code local → chạy trên Prefect HQ đã deploy sẵn

📖 Primary Source
Prefect 3 — Deploy Overview — tài liệu chính thức về deployment workflow.

Bức tranh tổng thể

Khi bạn nói "đưa code lên Prefect HQ", thực ra có 3 thành phần hoạt động cùng nhau:


  ┌─────────────────────────────────────────────────────────────┐
  │                   PREFECT HQ SERVER                         │
  │                (đã deploy sẵn trên server)                  │
  │                                                             │
  │  ┌─────────────┐  ┌──────────────┐  ┌──────────────────┐   │
  │  │ Deployments │  │  Flow Runs   │  │    Artifacts     │   │
  │  │ (metadata)  │  │  (tracking)  │  │  (reports, logs) │   │
  │  └──────▲──────┘  └──────▲───────┘  └──────────────────┘   │
  │         │                │                                  │
  └─────────┼────────────────┼──────────────────────────────────┘
            │                │
    ① đăng ký           ③ báo cáo
    deployment           kết quả
            │                │
  ┌─────────┴────────────────┴──────────────────────────────────┐
  │                    WORKER MACHINE                            │
  │          (máy thực thi code — có thể cùng server)           │
  │                                                             │
  │  ┌──────────────┐     ┌─────────────────────────────────┐   │
  │  │   Worker     │────▶│  prefect_flow.py                │   │
  │  │ (polling HQ) │     │  + config.json                  │   │
  │  │              │     │  + toàn bộ api_ingestion/       │   │
  │  └──────────────┘     └─────────────────────────────────┘   │
  │                                                             │
  │  ② Worker poll HQ, thấy scheduled run → pull code → chạy   │
  └─────────────────────────────────────────────────────────────┘

  ┌─────────────────────────────────────────────────────────────┐
  │                    YOUR LOCAL MACHINE                        │
  │                                                             │
  │  prefect deploy  ───────────────────▶  đăng ký lên HQ ①    │
  │  (chỉ gửi metadata, KHÔNG gửi code)                        │
  └─────────────────────────────────────────────────────────────┘
⚠️ Hiểu sai phổ biến (từ Airflow mindset)

Trong Airflow, bạn copy DAG file vào dags/ folder → scheduler tự parse → chạy.

Trong Prefect, prefect deploy KHÔNG upload code. Nó chỉ đăng ký metadata (tên flow, schedule, parameters) lên HQ. Code phải có sẵn trên worker machine — qua Git clone, Docker image, hoặc shared filesystem.

Bước 1: Kết nối local → HQ Server

Chỉ cần 1 biến môi trường:

# Trỏ Prefect CLI đến server HQ đã deploy
# Thay IP/domain thật của server

# PowerShell (Windows)
$env:PREFECT_API_URL = "http://your-prefect-server:4200/api"

# Bash (Linux/Mac)
export PREFECT_API_URL="http://your-prefect-server:4200/api"

# Kiểm tra kết nối
prefect version         # Xem version
prefect server health   # Phải trả về "healthy"
💡 Set vĩnh viễn

Để không phải set mỗi lần mở terminal:

# Lưu vào Prefect profile
prefect config set PREFECT_API_URL="http://your-prefect-server:4200/api"

# Kiểm tra
prefect config view

Bước 2: Tạo prefect.yaml — bản thiết kế deployment

File prefect.yaml nằm ở root thư mục api_ingestion/, khai báo:

  • Tên deployment — hiển thị trên HQ
  • Entrypoint — file + function chứa @flow
  • Work Pool — worker nào sẽ chạy code
  • Schedule — cron expression
  • Parameters — giá trị mặc định cho flow
  • Pull step — cách worker lấy code (Git, local, Docker)
# prefect.yaml — đặt tại d:\...\api_ingestion\prefect.yaml

# Pull step: cách Worker lấy code về để chạy
pull:
  - prefect.deployments.steps.git_clone:
      repository: https://github.com/ThinhITK57/coding-interview.git
      branch: enterprise-elt-pipeline
      access_token: null  # hoặc dùng Prefect Secret Block

# Deployments: có thể khai báo nhiều deployment cùng lúc
deployments:

  # --- Deployment cho DEV ---
  - name: clarizen-entity-query-dev
    entrypoint: working/api_ingestion/prefect_flow.py:api_ingestion_pipeline
    work_pool:
      name: dev-pool            # Work Pool phải tồn tại trên HQ
      work_queue_name: default
    parameters:
      config_path: config.json
      endpoint_name: entity_query
      env: dev
      spark_master: "local[*]"
    schedule:
      cron: "0 8 * * 1-5"      # 8AM thứ 2-6
      timezone: "Asia/Ho_Chi_Minh"

  # --- Deployment cho PROD ---
  - name: clarizen-entity-query-prod
    entrypoint: working/api_ingestion/prefect_flow.py:api_ingestion_pipeline
    work_pool:
      name: prod-pool
      work_queue_name: critical
    parameters:
      config_path: config.json
      endpoint_name: entity_query
      env: prod
      spark_master: "spark://master:7077"
    schedule:
      cron: "0 2 * * *"        # 2AM hàng ngày
      timezone: "Asia/Ho_Chi_Minh"
    job_variables:
      env:                      # Biến môi trường inject vào runtime
        API_KEY: "{{ prefect.blocks.secret.clarizen-api-key }}"
        SPARK_HOME: "/opt/spark"
💡 Airflow mapping

prefect.yaml = Airflow airflow.cfg + DAG schedule + Connection config gộp lại 1 file. Nhưng version-controlled cùng code — không phải config riêng trên server.

Bước 3: Deploy (đăng ký metadata lên HQ)

# cd vào thư mục chứa prefect.yaml
cd d:\dataguystory\coding-interview-university\working\api_ingestion

# Deploy TẤT CẢ deployments trong prefect.yaml
prefect deploy --all

# Hoặc deploy 1 cái cụ thể
prefect deploy --name clarizen-entity-query-dev

# Kiểm tra trên HQ
prefect deployment ls

Sau lệnh này, vào HQ dashboard → Deployments tab → thấy deployment vừa tạo với schedule, parameters.

⚠️ Nhắc lại: deploy ≠ upload code

prefect deploy chỉ gửi metadata (tên, schedule, params, entrypoint path). Code vẫn nằm trên Git repo hoặc worker machine. Worker sẽ pull code theo pull step khi chạy.

Bước 4: Chạy Worker trên server

Worker là process chạy trên máy thực thi (cùng server HQ hoặc máy riêng), liên tục poll HQ để lấy scheduled runs và chạy code.

# Trên WORKER MACHINE (server thực thi code)

# 1. Set API URL trỏ về HQ server
export PREFECT_API_URL="http://your-prefect-server:4200/api"

# 2. Cài dependencies
pip install prefect pyspark==2.3.2

# 3. Start worker cho pool cụ thể
prefect worker start --pool dev-pool

# Worker sẽ:
# → Poll HQ mỗi vài giây
# → Thấy scheduled run → pull code từ Git
# → Chạy prefect_flow.py:api_ingestion_pipeline
# → Báo kết quả + logs + artifacts về HQ
📌 Airflow equivalent

Worker = Airflow Celery Worker hoặc Local Executor. Work Pool = Airflow Pool. Nhưng Prefect Worker tự pull code, không cần shared dags/ folder.

Quản lý môi trường: 3 chiến lược

Bạn nói đúng — phải "control code để khớp với môi trường". Có 3 cách, từ đơn giản đến nâng cao:

Cách 1: Flow Parameters (bạn đã có!)

Code prefect_flow.py của bạn đã có env parameter:

@flow
def api_ingestion_pipeline(
    endpoint_name: str = "entity_query",
    env: str = "dev",        # ← switch môi trường tại đây
    spark_master: str = "local[*]",
):
    ...

Mỗi deployment set parameters.env khác nhau → cùng code, khác hành vi:

# prefect.yaml
deployments:
  - name: dev-pipeline
    parameters:
      env: dev
      spark_master: "local[*]"

  - name: prod-pipeline
    parameters:
      env: prod
      spark_master: "spark://master:7077"

Cách 2: Job Variables (inject env vars vào runtime)

# prefect.yaml — inject biến môi trường theo deployment
deployments:
  - name: prod-pipeline
    job_variables:
      env:
        API_KEY: "{{ prefect.blocks.secret.prod-api-key }}"
        DATABASE_URL: "{{ prefect.blocks.secret.prod-db-url }}"
        SPARK_HOME: "/opt/spark-2.3.2"

Code Python đọc bằng os.getenv("API_KEY") — không hardcode secret trong code.

Cách 3: Prefect Variables + Blocks (quản lý trên HQ UI)

# Tạo Variable trên HQ (qua CLI hoặc UI)
prefect variable set spark_master_dev "local[*]"
prefect variable set spark_master_prod "spark://master:7077"

# Tạo Secret Block cho API key
prefect block create secret/clarizen-api-key

# Trong code Python, đọc Variable:
from prefect.variables import Variable

spark_master = Variable.get("spark_master_" + env)

✈️ Airflow

  • Variable.get("key")
  • Connection cho DB/API credentials
  • Quản lý trên Airflow UI

🔷 Prefect

  • Variable.get("key") ← gần giống!
  • Secret Block cho credentials
  • Quản lý trên HQ UI hoặc CLI

Quy trình thực tế hàng ngày


  Viết/sửa code    Push Git     Deploy metadata     Worker chạy
  ─────────────  ─────────────  ───────────────  ──────────────────
                                                   
  prefect_flow.py   git push    prefect deploy     Worker poll HQ
       │               │            │                    │
       ▼               ▼            ▼                    ▼
  Test local:      Code lên     HQ biết flow     Worker git clone
  python            GitHub      mới/update       → chạy flow
  prefect_flow.py                               → report về HQ
  --dry-run

  ┌────────────────────────────────────────────────────────────┐
  │  🔄 CI/CD: Có thể tự động hóa bước deploy bằng           │
  │     GitHub Actions: git push → prefect deploy --all       │
  └────────────────────────────────────────────────────────────┘

Checklist trước khi deploy

✅ Pre-deployment Checklist
  1. ☐ PREFECT_API_URL trỏ đúng HQ server
  2. ☐ prefect server health → "healthy"
  3. ☐ Work Pool đã tạo trên HQ (dev-pool, prod-pool)
  4. ☐ Worker đang chạy trên server: prefect worker start --pool dev-pool
  5. ☐ Code đã push lên Git (branch đúng)
  6. ☐ prefect.yaml có pull step đúng Git repo + branch
  7. ☐ Dependencies cài đủ trên worker machine (prefect, pyspark)
  8. ☐ Secrets tạo xong trên HQ (API keys, DB URLs)
  9. ☐ Dry-run local pass: python prefect_flow.py --dry-run

Kiểm tra hiểu biết
