1. Airflow → Prefect Mapping Table

Bạn đã biết Airflow, nên đây là bảng "Rosetta Stone" giúp translate kiến thức:

Concept Airflow Prefect 3 Khác biệt chính
Pipeline DAG @flow Prefect flow = hàm Python thường, không cần khai báo DAG object
Unit of work Operator / Task @task Prefect task = hàm Python thường, return value trực tiếp (không cần XCom)
Truyền data XCom (push/pull) Python return value Không cần serialize. Task A return → Task B nhận trực tiếp qua argument
Schedule schedule_interval Deployment + cron Schedule nằm ở deployment, không ở flow definition
Dashboard Airflow Webserver Prefect HQ (Cloud/Server) HQ có Artifacts, Automations, Events — Airflow webserver không có
Connection Connection (UI/CLI) Block / Variable Prefect Blocks = typed storage cho secrets, DB URLs, etc.
Retry retries=3 retries=3, retry_delay_seconds=[30,120] Prefect hỗ trợ progressive delay (array), Airflow dùng retry_delay cố định
Logging self.log.info() get_run_logger().info() Logs tự động gắn vào flow run trên HQ, searchable
Deployment DAG file → dags/ folder prefect deploy Không cần copy file. Deploy chỉ đăng ký metadata lên server
Concurrency Pool (slots) Concurrency Limit (token bucket) Prefect dùng global concurrency limits, linh hoạt hơn Airflow pools
💡 Key Insight
Sự khác biệt lớn nhất: Airflow là configuration-as-code (khai báo DAG object rồi add operators). Prefect là code-as-code (viết Python bình thường, gắn decorator).

2. Anatomy: Flow Code của bạn

Mở file prefect_flow.py và nhìn cấu trúc. Mỗi phần được đánh dấu bằng comment section:

# Cấu trúc tổng quan prefect_flow.py

# 1. Imports
from prefect import flow, task, get_run_logger
from prefect.artifacts import create_markdown_artifact, create_table_artifact
from prefect.concurrency.sync import concurrency

# 2. Task definitions (= Airflow Operators)
@task(name="load_config", tags=["config"], retries=0)
def load_and_validate_config(config_path, env):
    ...

@task(name="extract_from_api", retries=2, retry_delay_seconds=[30, 120])
def extract_from_api(config, endpoint_name, staging_dir):
    ...

@task(name="transform_with_spark", retries=1)
def transform_with_spark(staging_dir, output_path, ...):
    ...

@task(name="run_quality_checks")
def run_quality_checks(output_path, ...):
    ...

@task(name="publish_daily_report")
def publish_daily_report(job_summary, quality_report):
    ...

# 3. Flow definition (= Airflow DAG)
@flow(name="api_ingestion_pipeline")
def api_ingestion_pipeline(endpoint_name, env, ...):
    # Task dependencies = just function calls!
    config = load_and_validate_config(config_path, env)
    result = extract_from_api(config, endpoint_name, staging_dir)
    transform = transform_with_spark(staging_dir, output_path, ...)
    report = run_quality_checks(output_path, ...)
    publish_daily_report(summary, report)

# 4. CLI entrypoint (argparse)
if __name__ == "__main__":
    api_ingestion_pipeline(...)

3. So sánh trực quan: Cùng logic, 2 style

✈️ Airflow

# Khai báo DAG object
dag = DAG(
    "api_ingestion",
    schedule_interval="0 2 * * *",
)

# Khai báo Operator
extract = PythonOperator(
    task_id="extract",
    python_callable=extract_fn,
    dag=dag,
)

transform = PythonOperator(
    task_id="transform",
    python_callable=transform_fn,
    dag=dag,
)

# Khai báo dependency
extract >> transform

🔷 Prefect

# Không cần DAG object

@task
def extract(config):
    return data

@task
def transform(data):
    return result

@flow
def pipeline():
    # Dependency = function call!
    data = extract(config)
    result = transform(data)

# KHÔNG ở code
⚠️ Airflow mindset trap
Trong Airflow, bạn phải khai báo extract >> transform để set dependency. Trong Prefect, dependency tự động xác định qua data flow: transform(extract(config)) — Prefect biết transform phụ thuộc extract vì nó nhận kết quả của extract.

4. 5 Feature HQ bạn đang dùng trong prefect_flow.py

4.1 Task Retries + Progressive Delay

@task(
    name="extract_from_api",
    retries=2,                      # Retry tối đa 2 lần
    retry_delay_seconds=[30, 120],  # Lần 1: chờ 30s, lần 2: chờ 120s
)

Airflow equivalent: retries=2, retry_delay=timedelta(seconds=30) — nhưng Airflow chỉ có 1 delay cố định, không progressive.

4.2 Task Tags

@task(tags=["extraction", "api"])

Tags xuất hiện trên HQ UI → bạn filter task runs theo tag. Ví dụ: xem tất cả task liên quan api đang fail.

4.3 Structured Logging

log = get_run_logger()
log.info("Page %d extracted: %d records", batch.page_number, total_records)

Logs tự gắn vào flow run trên HQ dashboard. Airflow equivalent: self.log.info() trong Operator, nhưng trên Prefect HQ logs searchable theo keyword.

4.4 Concurrency Limits

with concurrency("clarizen-api", occupy=1):
    # Chỉ 1 flow run được hit API cùng lúc
    for batch in extractor.iterate_batches(endpoint_config):
        writer.write_batch(batch)

Giống Airflow Pool nhưng flexible hơn: token-bucket based, có thể apply cho bất kỳ code block nào, không chỉ task.

4.5 Artifacts (Markdown + Table)

# Markdown report → hiển thị trên HQ Artifacts tab
create_markdown_artifact(
    key="daily-report-tasks",
    markdown=markdown_report,
    description="Daily ingestion report for tasks",
)

# Table artifact → bảng column stats
create_table_artifact(
    key="column-stats-tasks",
    table=table_data,  # List of dicts
)

Airflow KHÔNG CÓ tính năng tương đương. Artifacts là điểm mạnh riêng của Prefect HQ — bạn publish markdown reports, bảng thống kê trực tiếp lên dashboard.

5. Hands-on: Chạy thử pipeline

Cài Prefect

pip install prefect

Kiểm tra: prefect version — phải là 3.x

Chạy Prefect Server (local HQ dashboard)

# Terminal 1: Khởi động Prefect server
prefect server start

Mở browser: http://localhost:4200 — đây là HQ dashboard local.

Chạy flow dry-run

# Terminal 2: cd vào thư mục api_ingestion
cd d:\dataguystory\coding-interview-university\working\api_ingestion

# Dry run = chỉ validate config, không gọi API
python prefect_flow.py --endpoint entity_query --env dev --dry-run

Quay lại HQ dashboard → Flow Runs tab → bạn sẽ thấy flow run với trạng thái Completed.

Khám phá HQ Dashboard

Trên HQ (localhost:4200), click vào flow run vừa tạo:

  • Graph tab: Xem task dependency graph (giống Airflow Grid view)
  • Logs tab: Xem structured logs theo thời gian
  • Artifacts tab: Xem markdown reports (nếu chạy full, không dry-run)
  • Parameters tab: Xem input params của flow run

Deploy as scheduled job (bonus)

# Tạo deployment chạy daily lúc 2AM
prefect deploy prefect_flow.py:api_ingestion_pipeline \
    --name "clarizen-daily" \
    --cron "0 2 * * *" \
    --pool default-agent-pool

Quay lại HQ → Deployments tab → thấy schedule. Đây là equivalent của Airflow DAG schedule.
